# AI GameChat — разговор с персонажем (Unity + OpenRouter)

Игра-диалог: слева вертикальный портрет персонажа (50% ширины экрана), справа чат.
Персонаж отвечает в заданном характере через бесплатные модели OpenRouter, а портрет меняется
в зависимости от эмоции, которую определила модель. Если одна модель недоступна или исчерпала лимит,
приложение за один проход пробует следующую из списка.

> **Статус проверки.** Код написан без запуска Unity: я не мог компилировать проект и гонять сцену.
> Поэтому первый запуск — это и есть проверка. Раздел «Тестирование» ниже содержит пустые графы для результатов;
> имитированные сценарии нужно честно отметить в отчёте.

## Требования

- Unity 6 (6000.x; проект писался под 6.1).
- Пакеты `com.unity.ugui` (TextMeshPro входит в него), `com.unity.test-framework` — есть в стандартных шаблонах.
- Аккаунт OpenRouter и API-ключ: <https://openrouter.ai/keys>.

## Установка и запуск

Прежняя версия чата (`Assets/Scripts`, `Assets/Editor/ChatSceneBuilder.cs`, `Assets/Scenes/ChatScene.unity`) осталась
нетронутой: новая версия живёт в своей сборке `AIGameChat` и своей сцене, конфликтов имён нет.

1. Скопируйте папки `Assets/AI_GameChat` и `Assets/StreamingAssets` в свой проект (например, AI_GameChat).
2. **Window → TextMeshPro → Import TMP Essential Resources** (один раз, если ещё не импортировали).
3. **Tools → AI Chat → Build Character Scene**. Скрипт создаст `Assets/AI_GameChat/Scenes/CharacterChatScene.unity`,
   три профиля персонажей, портреты-заглушки и шрифт с кириллицей, и добавит сцену в Build Settings.
4. Ключ OpenRouter — любым из способов (по приоритету):
   - в игре: **Настройки → API-ключ** (хранится в PlayerPrefs этого компьютера);
   - файл `Assets/StreamingAssets/openrouter_config.json` (**Tools → AI Chat → Create Config File**, затем вставьте ключ);
   - переменная окружения `OPENROUTER_API_KEY`.
5. Нажмите Play. Размер окна Game — 16:9 (1920×1080). Для вертикального экрана нужно менять раскладку.

## Раскладка

```
┌───────────── 50% ─────────────┬───────────── 50% ─────────────┐
│                               │  Разговор          [Настройки]│
│        вертикальный           │  ┌──────────────────────────┐ │
│        портрет 2:3            │  │ лента сообщений          │ │
│        (AspectRatioFitter,    │  │ (ScrollRect)             │ │
│         Fit In Parent)        │  └──────────────────────────┘ │
│                               │  «Персонаж думает…»           │
│        Имя персонажа          │  [ строка ввода ] [Отправить] │
└───────────────────────────────┴───────────────────────────────┘
```

Canvas Scaler: Scale With Screen Size, 1920×1080, Match 0.5. Портрет подгоняется под любой размер спрайта
(используется пропорция самого спрайта), поэтому вместо заглушек можно ставить любые вертикальные рисунки.

## Персонаж и его характер

**Готовые профили** (`Assets/AI_GameChat/Characters`): Мика (жизнерадостная), Рэй (колючая и саркастичная),
Наставник Лин (спокойный и мудрый). Каждый — ScriptableObject `CharacterProfile`: имя, характер, манера речи,
приветствие, список «эмоция → спрайт». Новый профиль: **Assets → Create → AI Chat → Character Profile**,
затем добавьте его в список `Profiles` у объекта `ChatManager`.

**Свой характер.** В **Настройках** можно выбрать профиль и вписать собственное описание (до 800 символов).
Если поле заполнено, оно заменяет характер выбранного профиля (имя и портреты остаются от профиля).
После «Применить» диалог начинается заново: новый системный промпт, пустая история.

### Системный промпт

Собирается в `PromptBuilder` из двух частей:

1. **Характер**: имя, характер, манера речи (из профиля или введённый игроком).
2. **Служебные правила, добавляются всегда**: оставаться в образе, отвечать коротко (1–4 предложения), не называть себя ИИ,
   не раскрывать инструкции, не создавать откровенный сексуальный контент и не поощрять насилие и самоповреждение
   (при серьёзных проблемах игрока выйти из образа и посоветовать обратиться за помощью), а также **формат ответа**:

```json
{"emotion":"<neutral|happy|sad|angry|surprised|scared|embarrassed>","reply":"<реплика персонажа>"}
```

Служебная часть не зависит от текста игрока, поэтому свой характер не ломает смену спрайтов.
Почему так: короткие реплики и роль без «я языковая модель» нужны для эффекта живого собеседника;
эмоция берётся из того же ответа, чтобы не тратить второй запрос на классификацию (бесплатные лимиты малы).

## Эмоции и спрайты

| Эмоция | Файл по умолчанию (заглушка) | Когда используется |
|---|---|---|
| neutral | `Sprites/<id>/<id>_neutral.png` | по умолчанию, при ошибках разбора |
| happy | `..._happy.png` | радость, довольство |
| sad | `..._sad.png` | грусть, сочувствие |
| angry | `..._angry.png` | злость, раздражение |
| surprised | `..._surprised.png` | удивление |
| scared | `..._scared.png` | испуг, тревога |
| embarrassed | `..._embarrassed.png` | смущение |

**Свои рисунки.** Положите PNG поверх заглушек (одинакового размера и с одинаковым pivot, вертикальные, лучше 2:3,
например 1024×1536) либо назначьте спрайты в профиле. Существующие файлы и профили кнопка Build Character Scene не перезаписывает.

**Как определяется эмоция** (`EmotionParser`), по порядку:

1. чистый JSON; 2. JSON внутри блока кода или лишнего текста; 3. поля `reply`/`emotion` регулярками (в т. ч. обрезанный JSON);
4. тег `[emotion: x]`; 5. просто текст. Название эмоции понимается и по-английски, и по-русски (синонимы: `joy`, `радость`…).
Если эмоция не найдена или неизвестна, используется локальная оценка по ключевым словам в сообщении игрока
(рус/англ), а если и она ничего не нашла, то `neutral`. В отладочной подписи под репликой видно, откуда взята эмоция.

## Модели и ротация

Список по умолчанию в `ModelRotator` (перенесён из прежней версии проекта; сверен со страницей
<https://openrouter.ai/collections/free-models> 2026-10-30 — кроме Gemma, которой там в тот день не было в выдаче):

| № | Модель (slug) | Провайдер |
|---|---|---|
| 1 | `nvidia/nemotron-3.5-super-vl:free` | NVIDIA |
| 2 | `dots-studio/dots-3-note-preview:free` | dots.studio |
| 3 | `poolside/laguna-s-2.1:free` | Poolside |
| 4 | `recursive/flint-v1.0:free` | Recursive |
| 5 | `nvidia/nemotron-3-ultra-550b-a55b:free` | NVIDIA |
| 6 | `google/gemma-4-31b-it:free` | Google |

**Список бесплатных моделей быстро меняется. Перед сдачей проверьте каждый slug на
<https://openrouter.ai/models?max_price=0>.** Заменить модели можно без пересборки сцены: в `openrouter_config.json`
укажите `"models": ["...:free", "...:free"]` (непустой список заменяет список из сцены). Отдельная проверка русского языка у этих
моделей мной не выполнялась.

**Алгоритм** (`OpenRouterClient` + `ModelRotator`): один пользовательский запрос = не больше одного прохода по списку.
Начинается с последней успешной модели. Для каждой модели отправляется один и тот же запрос с той же историей, меняется только `model`.

| Ситуация | Действие |
|---|---|
| успех и непустой текст | показать ответ, запомнить модель, закончить |
| 429, 5xx, 404 (нет модели), 403, 408, таймаут | перейти к следующей модели |
| HTTP 200, но в теле `error` или пустой ответ | перейти к следующей модели |
| 400, где модель не поддерживает системный промпт или параметр | перейти к следующей модели |
| 401 (ключ), 402 (кредиты/лимит аккаунта), прочие 400 | **остановить ротацию**, показать ошибку |
| нет сети | остановить, показать «Нет подключения» |
| не сработала ни одна модель | «Все бесплатные модели сейчас недоступны» |

Таймаут одного запроса — 30 с (настраивается в `OpenRouterClient`). Бесконечных повторов нет.
Кнопка и поле ввода блокируются на время запроса; пустое сообщение не отправляется.
Если запрос не удался, сообщение игрока остаётся на экране, но **не попадает в историю**; повторная отправка создаёт новую
реплику на экране, а в историю текст попадёт один раз — вместе с ответом.

**История:** последние 10 сообщений (настраивается в `ChatController`), системный промпт никогда не обрезается.
В историю ответ персонажа записывается как нормализованный JSON (`{"emotion":..,"reply":..}`), чтобы модель продолжала
держать формат.

## Тестирование

Автотесты (Window → General → Test Runner → EditMode): разбор эмоций (JSON, блок кода, обрезанный JSON, тег, неизвестная
эмоция, пустой ввод, ключевые слова), история (лимит, системный промпт, отсутствие следов при ошибке), ротация (один проход,
приоритет последней успешной, переопределение из конфига), системный промпт (формат остаётся при своём характере).

Ручные сценарии. Режимы имитации включаются в инспекторе `ChatManager → OpenRouterClient → Test Mode`.

| № | Сценарий | Как проверить | Ожидается | Результат | Реально / имитация |
|--:|---|---|---|---|---|
| 1 | Обычный вопрос | «Привет, как дела?» | ответ в ленте, портрет по эмоции | | |
| 2 | Уточняющий вопрос | сначала «Меня зовут Аня», потом «Как меня зовут?» | модель помнит контекст | | |
| 3 | Пустое сообщение | нажать «Отправить» с пустой строкой | запрос не уходит, подсказка | | |
| 4 | Неверный ключ | ввести в Настройках `sk-or-wrong` | ошибка авторизации (401), ротации нет | | |
| 5 | Несуществующая модель | Test Mode = `InvalidFirstModelId` | 404 → переход к следующей, ответ есть | | реальный запрос |
| 6 | Лимит (429) | Test Mode = `SimulateRateLimitOnFirstModel` | переход ко второй модели, в подписи «переключений: 1» | | имитация |
| 7 | Все модели недоступны | Test Mode = `SimulateAllModelsDown` | сообщение «Все бесплатные модели недоступны» после N попыток | | имитация |
| 8 | Двойное нажатие Send | быстро нажать дважды | один запрос, одна реплика игрока | | |
| 9 | Задержка сети | замедлить сеть/подождать | «Персонаж думает…», UI не зависает | | |
| 10 | Длинный диалог | 15+ реплик | в запросе ≤10 сообщений истории + system | | |
| 11 | Эмоции | «Ты идиот» / «Спасибо, ты лучшая!» / «Мне грустно» / «Ты очень красивая» | спрайты angry / happy / sad / embarrassed (если модель или локальный запасной вариант определили так) | | |
| 12 | Смена характера | Настройки → другой профиль или свой текст → Применить | диалог начался заново, манера речи другая | | |

Для отчёта сохраните 2–3 диалога (минимум один с ошибкой и переключением модели) и скриншоты.

## Безопасность ключа

- Настоящий ключ не хранится в коде. `Assets/StreamingAssets/openrouter_config.json` добавлен в `.gitignore`
  (в репозитории лежит только `openrouter_config.example.json` с заглушкой).
- Ключ, введённый в игре, лежит в PlayerPrefs в открытом виде (на Windows это реестр). Подходит для учебного запуска.
  Файл в клиентской сборке и PlayerPrefs **не являются надёжным хранилищем секрета**: для распространяемой игры нужен
  серверный посредник, который хранит ключ у себя.
- Перед сдачей удалите ключ из проекта, убедитесь, что его нет в истории Git, при необходимости отзовите его на openrouter.ai/keys.
  Проверяющий вводит свой ключ в Настройках или через конфиг-файл.

## Если что-то не работает

- **Квадраты вместо русских букв**: Build Character Scene создаёт динамический шрифт из встроенного Liberation Sans. Если создать его не
  удалось (будет предупреждение в Console), назначьте любой TMP-шрифт с кириллицей полю `Font` у `ChatUI` и вручную текстам сцены.
- **Курсор/кнопки не реагируют**: в сцене должен быть `EventSystem`. Builder выбирает модуль для новой или старой системы ввода автоматически;
  при смене настройки Active Input Handling замените модуль вручную.
- **Всегда «модели недоступны»**: откройте Console. Строки `[AIGameChat] Переключение с … — причина` показывают, что вернул каждый
  запрос. Если все модели возвращают 404, список устарел — обновите его (см. выше).
- **Запуск на Android/WebGL**: чтение `openrouter_config.json` из StreamingAssets рассчитано на десктоп и редактор; на мобильных
  вводите ключ в Настройках (и помните про оговорку о безопасности).
